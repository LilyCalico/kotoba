# 遊び方を UI 言語と別の軸としてゲーム開始で受け、web が UI 言語から決める

## ステータス

採用

## コンテキスト

ゲームには 2 つの遊び方がある（`docs/specifications/game.md`）。英語の UI では設問を手がかりにスウェーデン語の単語を当て（単語当て）、日本語の UI ではスウェーデン語の単語と読みを見て意味を当てる（意味当て）。

api はゲーム開始の `locale` で設問・ヒント・結果の言語を決める。遊び方によって、開始の応答（設問か、単語と読みか）、ヒントの出どころ、入力の判定が変わる。どこで遊び方を決め、api にどう伝えるかを決める必要がある。

満たすべき要件は次のとおり。

1. 日本語の UI では意味当て、英語の UI では単語当てで遊ぶ。プレイヤーに遊び方を選ばせる設定は足さない
2. api のコードが、遊び方の分岐を UI 言語の値から読み取らずに済む
3. 意味当ての実装を api から画面まで何度かに分けて入れる間も、各段階で今の画面が動き続ける
4. 意味当てのヒントは日本語でだけ持つ。英語の UI で意味当てを始められない

## 決定

| 項目 | 決めたこと |
| --- | --- |
| api | ゲーム開始のリクエストに `mode`（`guess_word` \| `guess_meaning`、省略時は `guess_word`）を足す。`locale` とは別の軸として受け、ゲームに保存する。ヒント・入力の判定は保存した `mode` で分ける |
| 組の検証 | `guess_meaning` は `locale: "ja"` のときだけ受け、`en` との組は `validation_error` にする |
| 開始の応答 | `GameStart` を `mode` の判別共用体にする。単語当ては `teaser`、意味当ては `word` と `reading` を返す |
| web | UI 言語から遊び方を決めて `mode` を送る（`ja` は `guess_meaning`、`en` は `guess_word`）。対応は web の 1 か所に置く |

## 検討した選択肢

### api が `locale` から遊び方を決める

リクエストは変えず、api が `locale: "ja"` なら意味当てで始める。リクエストの項目が増えず、組の検証もいらない。

一方で、api の分岐が「日本語なら」という UI 言語の条件になり、設問・ヒントの言語を決める `locale` が遊び方まで背負う（要件 2）。`ja` の UI で単語当てに戻す、英語のヒントを書いて英語の UI でも意味当てを遊べるようにする、といった変更のたびに api の分岐を書き換えることになる。また、api を変えた時点で `/ja` の遊び方が切り替わるため、画面の対応が入るまで `/ja` が壊れる（要件 3）。

### プレイヤーが遊び方を選ぶ設定を足す

スタート画面に「単語を当てる / 意味を当てる」の切り替えを置き、UI 言語と独立に選ばせる。

どちらの UI 言語でも両方の遊び方を選べるが、英語の意味当てのヒントを書き足す必要がある（要件 4）。設定を増やさないという要件 1 にも反する。api は `mode` を別の軸として受けるため、後から設定を足すときは web の対応を置き換えるだけで済む。

## 影響

- 遊び方の分岐は api では `mode`、web では UI 言語から `mode` を決める 1 か所に集まる
- `mode` の既定を `guess_word` にしたため、web が `mode` を送るまでは `/ja` も単語当てで動き続ける
- `GameStart` が判別共用体になり、web の状態は `mode` で最初の画面を分ける
- `guess_meaning` と `en` の組を検証で落とすため、英語の UI で意味当てを遊べるようにするには、英語の意味当てのヒントを書いてから検証を外す

## 見直しの条件

- プレイヤーが遊び方を選べるようにしたくなった場合。web の対応を設定に置き換える
- 英語の意味当てのヒントを書いた場合。組の検証を外す
