# UI 言語を URL のサブパスで分け、文言はライブラリを使わず型付きの辞書で持つ

## ステータス

採用

## コンテキスト

UI 言語は日本語と英語の 2 つ（`docs/specifications/game.md`「設定」）。api はゲーム開始の `locale` で設問・ヒント・結果の言語を決め、ゲームの間は変えない（`docs/specifications/api.md`）。web は、どの言語で画面を出し、どの `locale` でゲームを始めるかを決め、画面の文言を言語ごとに持つ必要がある。

満たすべき要件は次のとおり。

1. URL を共有したとき、同じ言語の画面が開く
2. 初めて来た人には、ブラウザの言語に合った画面を出す
3. ページは今と同じく静的に生成できる
4. 画面の文言（約 120）の訳し漏れを、実行前に見つけられる
5. web と api は同じホストに載り、`/api/v1` は api に届く（`vercel.json` の `rewrites`、ローカルでは `next.config.ts` の中継）。言語の振り分けがこれを妨げない

## 決定

| 項目 | 決めたこと |
| --- | --- |
| URL | ページとレイアウトを `app/[lang]/` に置き、`/ja`・`/en`・`/ja/play`・`/en/play` にする。`generateStaticParams` で 2 言語を生成し、`dynamicParams = false` でそれ以外を 404 にする |
| 振り分け | `proxy.ts` が、言語のない URL を、画面で切り替えた言語（cookie の `locale`）、Accept-Language で選んだ言語の順に決めた言語の URL へリダイレクトする。Accept-Language は品質値の高い順に主言語のサブタグを見て、`ja` か `en` に当たった最初のものを選び、どちらもなければ `en` にする |
| 切り替え | スタート画面のヘッダーに、もう一方の言語のスタート画面へのリンクを置く。押すと選んだ言語を cookie（`locale`、1 年）に残す。言語の付いた URL を開いただけでは cookie を書かない |
| 振り分けの対象外 | matcher で `/api/`・`/_next/`・`/_vercel/`・拡張子のあるパスを外す。Proxy は `next.config.ts` の rewrites より先に動くため、外さないと `/api/v1` の中継までリダイレクトされる |
| 言語の受け渡し | `[lang]` のレイアウトが `<html lang>`・React Aria の `I18nProvider`・言語のコンテキストに渡す。クライアントコンポーネントは `useLocale()` で引き、ゲーム開始の `locale` と画面内のリンクに使う |
| 文言 | ライブラリを入れず、`en` と `ja` の辞書を TypeScript のオブジェクトで持つ。`en` の形を型にし、`ja` を同じ型で書かせて、抜けを型検査で落とす。値を取る文言（待つ時間など）は関数にする |

## 検討した選択肢

### URL を変えず、cookie で言語を切り替える

`/` と `/play` のまま、選んだ言語を cookie に覚える。URL は短いままになる。

一方で、URL を共有しても受け取った人の cookie で言語が決まり、同じ画面が開かない（要件 1）。ページの内容が cookie で変わるため、静的に生成できない（要件 3）。

### next-intl を入れる

振り分け・辞書・複数形や日時の書式をまとめて持てる。

一方で、言語は 2 つ、文言は約 120 で、複数形の規則も日本語と英語の差は小さい。振り分けは数行、辞書は型付きのオブジェクトで足り、依存と設定（プラグイン・リクエストごとの設定ファイル）の分だけ重くなる。訳し漏れは、辞書の型で同じように見つけられる（要件 4）。

### Accept-Language の解釈に negotiator と @formatjs/intl-localematcher を使う

Next.js のガイドが例に挙げる組み合わせで、地域のサブタグや言語の近さまで扱える。

一方で、選ぶ先は `ja` と `en` の 2 つだけで、主言語のサブタグを品質値の順に見れば足りる。依存を 2 つ入れるほどの差がない。

## 影響

- URL に言語が入り、共有した画面がそのまま開く。どのページも 2 言語ぶん静的に生成される
- 言語のない URL は、毎回 1 度リダイレクトを挟む
- 画面で切り替えた言語を cookie に覚え、`/` に来たときはブラウザの言語より先にその言語に振り分ける。共有された URL は、cookie に関わらず URL の言語で開く
- 文言を足すときは、`en` の辞書に足すと `ja` が型検査で落ちるため、両方を同時に書くことになる

## 見直しの条件

- 対応する UI 言語が増え、複数形や数・日付の書式の差を辞書の関数で書き分けるのが重くなった場合。next-intl などのライブラリを検討する
- 言語ごとにドメインを分けたくなった場合
