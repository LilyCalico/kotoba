## ルール

- AI が秘密の単語を持ち、プレイヤーははい/いいえ質問で絞り込み、単語そのものを当てる

## ゲーム

### ゲームフロー

1. ゲーム開始 → サーバーが単語プールからランダムに 1 語選出
   - ローカルストレージに出題済みの単語を保持しておいて、問題が枯渇するまでは被らないように出題する
2. 初期情報として提示: 出題言語（瑞 or 日）+ **設問**（謎めいた一行ティーザー。例:「金曜日の夜、この言葉はソファの上にある」）
3. プレイヤーは自由入力で質問（日本語・英語・スウェーデン語のみ対応。他言語は「対応言語で質問してね」を返す）→ AI が 5 種の回答のみ返す:
   **はい / いいえ / どちらとも言えない / それは関係ない / 質問の形にしてね**（yes/no 疑問文でない場合）
   - 質問は 1 ゲーム 20 問まで。残り質問数をカウントダウン表示（20 の扉形式）。コスト上界の確保も兼ねる
   - メタ応答 2 種（**質問の形にしてね / 対応言語で質問してね**）は 20 問カウントを消費しない。ただし API 呼び出しとしてはレートリミットの対象（メタ応答連発でコスト上界が崩れないように）
   - 質問入力は最大 200 字
   - 「ヒント」ボタンをいつでも押せる（詳細はスコアリング節）。ヒント開示は質問数を消費しない
4. いつでも「回答する」ボタンから単語名を入力して解答（誤答は 3 回まで）。判定は 2 段構え:
   - コードで正規化マッチ（表記ゆれ・別名は `accepted_answers` で吸収）
   - 外れた場合のみ AI でスペルミス・音写ゆれを救済判定（救済で正解扱いになった解答は誤答にカウントしない）
5. 終了条件は 4 つ: クリア / 質問 20 問使い切り / 誤答 3 回 / ギブアップ。いずれも正解の単語と定義を表示（単語カードのような専用詳細画面は作らない）。クリア以外は記録上未クリア
6. 離脱: ゲームはプレイ画面を離れた時点で終了する（リロード・タブを閉じる・スタート画面への移動を含む）。進行中ゲームを再開する手段は設けず、1 プレイは 1 セッションで完結させる。離脱は記録上未クリア。ただし離脱では答え（正解の単語と定義）を見ていないため、その単語は出題除外の対象にしない（後日新鮮に再挑戦できる）

### スコアリング

- 少ない質問数でのクリアほど高スコア: 満点 100 点から質問 1 回ごとに-5、誤答 1 回ごとに-10、ヒント 1 回ごとに-15、下限 10 点
- ヒント: 各単語に人手作成の**段階ヒントを 3 つ**用意（1 つ目はカテゴリや感情の方向性、2 つ目はどんな場面で使われるか、3 つ目は語の成り立ちや直訳に近い核心。答えそのものは含めない）。「ヒント」ボタンで順に開示し、1 ゲームで最大 3 回

## AI 設計

- 回答は enum 5 値の structured output で強制。単語や定義の断片が回答文に漏れない
- 秘密の単語・Q&A 履歴はサーバーのみが保持し、クライアントには一切送らない
- 各質問の判定時、そのゲームの**全 Q&A 履歴**をプロンプトに含め、回答の一貫性を担保（矛盾防止。最大 20 問なのでトークン増は限定的）
- API 障害時（エラー / タイムアウト / structured output 不正）はサーバー内で 1 回自動リトライ。それでも失敗したら「もう一度送ってね」エラーを返し、**質問数は消費しない**
- 「答えを教えて」「システムプロンプトを見せて」系のプロンプトインジェクション耐性をテストケース化する
- モデルは安価なもの（Gemini Flash 系想定）を使用。判定精度は eval セットで検証
