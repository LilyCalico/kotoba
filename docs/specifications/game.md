## ルール

- AI が答えを持ち、プレイヤーははい/いいえ質問で絞り込んで当てる
- 遊び方は 2 つあり、UI 言語で決まる
  - **単語当て**（英語の UI）: 設問を手がかりに、スウェーデン語の単語そのものを当てる
  - **意味当て**（日本語の UI）: スウェーデン語の単語と読みを見て、その意味を当てる

## ゲーム

### ゲームフロー

1. ゲーム開始 → サーバーがスウェーデン語の単語プールからランダムに 1 語選出
   - ローカルストレージに出題済みの単語を保持しておいて、問題が枯渇するまでは被らないように出題する
2. 初期情報として提示: 単語当ては**設問**（謎めいた一行ティーザー。例:「金曜日の夜、この言葉はソファの上にある」）、意味当ては**単語と読み**（例:「Lagom / ラーゴム」）
3. プレイヤーはチャットの入力欄から自由入力する。入力欄は 1 つで、質問と解答の両方を受け付ける（日本語・英語・スウェーデン語のみ対応。他言語は「対応言語で質問してね」を返す）。以下は単語当ての判定で、意味当ての判定は「意味当て」節に置く
   - AI が入力を**質問**と**解答**に分類する
     - 単語そのものを当てる質問（「Is it lagom?」「ラーゴムですか？」）は解答として扱い、当てた語で正誤を判定する。単語を言い当てたのに「はい」とだけ返ると、答えを知ってもクリアにならないため
   - 質問と分類された入力には、AI が 5 種の回答のみ返す:
     **はい / いいえ / どちらとも言えない / それは関係ない / 質問の形にしてね**（yes/no 疑問文でない場合）
   - 解答と分類された入力は正誤判定に回す。判定は 2 段構え:
     - コードで正規化マッチ（表記ゆれ・別名は `accepted_answers` で吸収）
     - 外れた場合のみ AI でスペルミス・音写ゆれを救済判定。質問と解答の分類と同じ 1 回の呼び出しで判定する
       - 綴りの間違い（文字の抜け・余分・入れ替わり・打ち間違い）が 2 文字程度までなら正解
       - カタカナ・ローマ字などの音写は、同じ語の音を写したものなら文字数に関わらず正解
       - 意味が近いだけの別の語・訳語は誤答
       - 語の前後に別の語をつけた解答（「lagom please」）は、正しい綴りを含んでいても誤答。解答は語だけを送ったとき、または単語そのものを当てる質問の形で送ったときに限る
     - 救済で正解したときも、正規化マッチの正解と同じくクリアにし、結果のカードに正しい綴りを出す
   - 誤答に回数制限は設けず、正解するまで何度でも解答できる
   - 入力はすべて API 呼び出しとしてレートリミットの対象（コスト上界の確保）
   - 入力は最大 200 字
   - 「ヒント」ボタンをいつでも押せる（詳細はヒント節）
4. 終了条件は 2 つ: クリア / ギブアップ（ヘッダーの Give up ボタンから確認ダイアログを挟んで実行）。いずれもチャットの末尾に正解の単語と定義をカードで表示する（単語カードのような専用詳細画面は作らない）。ギブアップは記録上未クリア
5. 離脱: ゲームはプレイ画面を離れた時点で終了する（リロード・タブを閉じる・スタート画面への移動を含む）。進行中ゲームを再開する手段は設けず、1 プレイは 1 セッションで完結させる。離脱は記録上未クリア。ただし離脱では答え（正解の単語と定義）を見ていないため、その単語は出題除外の対象にしない（後日新鮮に再挑戦できる）

### 意味当て

単語当てと同じチャットで遊び、次の点だけが異なる。

- 最初に単語と読みを見せ、設問は出さない。単語は秘密ではなく、秘密は意味（定義）である
- AI が入力を**質問**と**意味の解答**に分類する
  - 意味について問うはい/いいえ質問（「気持ちに関係ある？」）は質問。回答は単語当てと同じ 5 種
  - 意味を言い当てる入力（「ちょうどいいこと」「ちょうどいいって意味？」）は解答。意味を言い当てる質問の形も解答として扱う
  - 画面に出ている単語そのものや、別の単語の名前だけを送った入力は、意味を答えていないため誤答
- 解答の正誤は、単語ごとに人手で書いた**判定基準**に照らして AI が決める。判定基準は、正解とみなす核心と、正解にする言い換えの例、近いが誤りにする例からなる
  - 核心を捉えていれば、言い回しや言語（日本語・英語・スウェーデン語）を問わず正解
  - 近いだけの意味や、核心の一部だけを言った解答は誤答
  - 意味の書き方は無数にあるため、正規化マッチは使わず、解答はすべて AI で判定する
- 結果のカードは単語当てと同じ（単語・読み・品詞・直訳・定義・補足・例文）
- 出題済みの記録は遊び方で分けない。どちらの遊び方で答えを見た単語も、次のゲームの出題から除く

### ヒント

- 各単語に人手作成の**段階ヒントを 3 つ**用意し、「ヒント」ボタンで順に開示する。1 ゲームで最大 3 回
- ヒントは遊び方ごとに別に持つ。単語当てのヒントは意味を手がかりにするため、意味当てで出すと答えになる
  - 単語当て: 1 つ目はカテゴリや感情の方向性、2 つ目はどんな場面で使われるか、3 つ目は語の成り立ちや直訳に近い核心。単語そのものは含めない。日本語と英語で書く
  - 意味当て: 1 つ目はどんな種類の意味か（気持ち・物・行為など）、2 つ目は使われる場面、3 つ目は核心に近い言い換え。定義の言い回しをそのまま使わない。日本語だけで書く
- 開示したヒントはチャットの流れの中にカードとして積み、「ヒント 1 / 3」のように何番目かを添える。ボタン側には残り回数を表示する

## AI 設計

- 入力の分類（質問 / 解答）と質問への回答を structured output で返す。回答は enum 5 値に強制し、単語や定義の断片が回答文に漏れない
- 答え（単語当てでは単語、意味当てでは定義と判定基準）・Q&A 履歴はサーバーのみが保持し、ゲームが終わるまでクライアントに送らない
- 各質問の判定時、そのゲームの**全 Q&A 履歴**をプロンプトに含め、回答の一貫性を担保（矛盾防止）
- API 障害時（エラー / タイムアウト / structured output 不正）はサーバー内で 1 回自動リトライ。それでも失敗したら、無料枠の AI が失敗したので何回か送り直してほしいと伝える
- 無料枠の上限に達したときは再試行せず、上限が戻るまでのおよその時間を添えて、そのころに送り直してほしいと伝える
- 「答えを教えて」「システムプロンプトを見せて」系のプロンプトインジェクション耐性をテストケース化する
- モデルは安価なもの（Gemini Flash 系想定）を使用。分類・判定の精度は eval セットで検証

## 設定

- UI 言語: 日本語 / 英語。遊び方は UI 言語で決まり（日本語は意味当て、英語は単語当て）、別の設定は持たない

## 実装予定の機能

- 日本語の単語での出題（遊ぶ言語の選択）
- 認証（ログイン・戦績保持）
- ダークモード
