## ルール

- AI が秘密の単語を持ち、プレイヤーははい/いいえ質問で絞り込み、単語そのものを当てる

## ゲーム

### ゲームフロー

1. ゲーム開始 → サーバーがスウェーデン語の単語プールからランダムに 1 語選出
   - ローカルストレージに出題済みの単語を保持しておいて、問題が枯渇するまでは被らないように出題する
2. 初期情報として提示: **設問**（謎めいた一行ティーザー。例:「金曜日の夜、この言葉はソファの上にある」）
3. プレイヤーはチャットの入力欄から自由入力する。入力欄は 1 つで、質問と解答の両方を受け付ける（日本語・英語・スウェーデン語のみ対応。他言語は「対応言語で質問してね」を返す）
   - AI が入力を**質問**と**解答**に分類する
   - 質問と分類された入力には、AI が 5 種の回答のみ返す:
     **はい / いいえ / どちらとも言えない / それは関係ない / 質問の形にしてね**（yes/no 疑問文でない場合）
   - 解答と分類された入力は正誤判定に回す。判定は 2 段構え:
     - コードで正規化マッチ（表記ゆれ・別名は `accepted_answers` で吸収）
     - 外れた場合のみ AI でスペルミス・音写ゆれを救済判定。質問と解答の分類と同じ 1 回の呼び出しで判定する
       - 綴りの間違い（文字の抜け・余分・入れ替わり・打ち間違い）が 2 文字程度までなら正解
       - カタカナ・ローマ字などの音写は、同じ語の音を写したものなら文字数に関わらず正解
       - 意味が近いだけの別の語・訳語は誤答
       - 語の前後に別の語をつけた解答（「lagom please」）は、正しい綴りを含んでいても誤答。解答は語だけを送ったときに限る
     - 救済で正解したときも、正規化マッチの正解と同じくクリアにし、結果のカードに正しい綴りを出す
   - 誤答に回数制限は設けず、正解するまで何度でも解答できる
   - 入力はすべて API 呼び出しとしてレートリミットの対象（コスト上界の確保）
   - 入力は最大 200 字
   - 「ヒント」ボタンをいつでも押せる（詳細はヒント節）
4. 終了条件は 2 つ: クリア / ギブアップ（ヘッダーの Give up ボタンから確認ダイアログを挟んで実行）。いずれもチャットの末尾に正解の単語と定義をカードで表示する（単語カードのような専用詳細画面は作らない）。ギブアップは記録上未クリア
5. 離脱: ゲームはプレイ画面を離れた時点で終了する（リロード・タブを閉じる・スタート画面への移動を含む）。進行中ゲームを再開する手段は設けず、1 プレイは 1 セッションで完結させる。離脱は記録上未クリア。ただし離脱では答え（正解の単語と定義）を見ていないため、その単語は出題除外の対象にしない（後日新鮮に再挑戦できる）

### ヒント

- 各単語に人手作成の**段階ヒントを 3 つ**用意（1 つ目はカテゴリや感情の方向性、2 つ目はどんな場面で使われるか、3 つ目は語の成り立ちや直訳に近い核心。答えそのものは含めない）。「ヒント」ボタンで順に開示し、1 ゲームで最大 3 回
- 開示したヒントはチャットの流れの中にカードとして積み、「ヒント 1 / 3」のように何番目かを添える。ボタン側には残り回数を表示する

## AI 設計

- 入力の分類（質問 / 解答）と質問への回答を structured output で返す。回答は enum 5 値に強制し、単語や定義の断片が回答文に漏れない
- 秘密の単語・Q&A 履歴はサーバーのみが保持し、クライアントには一切送らない
- 各質問の判定時、そのゲームの**全 Q&A 履歴**をプロンプトに含め、回答の一貫性を担保（矛盾防止）
- API 障害時（エラー / タイムアウト / structured output 不正）はサーバー内で 1 回自動リトライ。それでも失敗したら、無料枠の AI が失敗したので何回か送り直してほしいと伝える
- 無料枠の上限に達したときは再試行せず、上限が戻るまでのおよその時間を添えて、そのころに送り直してほしいと伝える
- 「答えを教えて」「システムプロンプトを見せて」系のプロンプトインジェクション耐性をテストケース化する
- モデルは安価なもの（Gemini Flash 系想定）を使用。分類・判定の精度は eval セットで検証

## 設定

- UI 言語: 日本語 / 英語

## 実装予定の機能

- 日本語の単語での出題（遊ぶ言語の選択）
- 認証（ログイン・戦績保持）
- ダークモード
