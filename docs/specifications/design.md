### トーン&マナー

- 方向性: **Y2K パステルのデスクトップ**。淡いピンクの方眼紙を地にし、昔のパソコンのウィンドウ・キーキャップ・読み込みバーを部品にする。ウィンドウは白い面に 1.5px の紺の罫とずらしたベタの影をとり、タイトルバーの色で何を載せているかを見分けさせる
- サイトを開くと、まずパソコンの画面に「Hej hej! / Jag heter Kotoba」が打ち込まれる起動画面を見せ、そこからスタート画面のウィンドウを開く
- 見せ場は 2 つに絞る。サイトを開いたときの打ち込みと、正解とギブアップで結果のウィンドウにホログラムのステッカーが貼られる瞬間である。ほかの動きは状態の変化を伝える短い出現にとどめる
- モバイル・デスクトップの両対応を同等品質で作り込む。画面幅ごとのレイアウトは「レスポンシブ設計」節で定める
- テーマはライトのみ。配色はすべてセマンティックトークン経由で参照し、ダークを足すときは値の差し替えだけで済む形にしておく

### 役割ごとの見た目

画面の要素は役割ごとに見た目を 1 つに決め、同じ見た目を別の役割に使わない。

| 役割 | 要素 | 見た目 |
| --- | --- | --- |
| 読ませるもの | 設問・ヒント・結果 | タイトルバー付きのウィンドウ。設問はラベンダーの「Question」、ヒントはピーチの「Hint 1 of 3」、結果はピンクの「You found it／The word was」。本文は Crimson Text |
| 回答 | 5 値の回答 | アイコン付きの太字の丸いピル。平たく影を持たない。Yes はライムに ✓、No はコーラルに ✕、Hard to say は空色に −、That's not related は白に破線の枠と切れた鎖、Try a yes-or-no question は黄に吹き出しの ? |
| 判定と案内 | 正誤のフィードバック、送信とヒントの失敗、期限切れ | 塗りも枠もない、アイコン付きの文字 |
| 応答待ち | 応答待ち | 回答のピルが入る位置の、ペリウィンクルのタイトルバー「Thinking…」を持つ小さなウィンドウ。中の読み込みバーのブロックが左から順に灯る。チャットの応答待ちが 2 秒を超えたら、ウィンドウの下に砂時計のアイコン付きの文字で「Sorry, give me a moment to think — this is taking a little longer than usual.」を添える（判定と案内と同じく塗りも枠もない） |
| ラベル | 結果の品詞 | ラベンダーの小さなピル。回答より小さく、アイコンを付けない |
| 発言 | プレイヤーの入力 | 紺の吹き出しに白い文字。右に寄せ、右下の角だけを尖らせる |
| 主ボタン | Start a game・Play again・ギブアップの確定 | ピンクのキーキャップ。紺の枠の内側にピンクの縁、その内側に横向きのグラデーションの面、紺の厚い影 |
| 送信 | 送信 | 角の丸い四角のキーキャップ。面は放射状のグラデーション |
| 副ボタン | ヒント・Cancel | 白い面に 1.5px の紺の枠と 2px の影。ダイアログのボタンの形 |
| 目立たせない操作 | ヘッダーの Give up、起動画面の Skip | 下線の付いた文字。枠も影も持たない |

- ウィンドウのタイトルバーの右端には、最小化・最大化・閉じるの箱を飾りとして置く。押せず、読み上げない
- スタート画面と結果のウィンドウは、後ろに白いウィンドウを 2 枚重ね、画面の主役にする
- ダイアログとトーストもウィンドウとして描く。ダイアログのタイトルバーはペリウィンクルで、文字を載せない
- ヒントの残りの回数は、ヒントボタンの中の読み込みバーの 3 つのブロックで示す。塗ったブロックが残りの数になる。読み上げでは「Show a hint, 2 left」のように数を伝える
- ボタンの文字はキーキャップのピンクの面に紺で置く。白い文字はピンクの面に対して 4.5:1 を満たさないため使わない

### 画面

| 画面 | 構成 |
| --- | --- |
| 起動 | ワードマーク、パソコン（ペリウィンクルの筐体・白い枠・空色からピンクへのグラデーションの画面）、その下の中央に「> Skip」。画面に「Hej hej!」と「Jag heter Kotoba」を 2 行で 1 文字ずつ打ち込み、末尾でカーソル「_」が点滅する |
| スタート | ワードマーク、ピンクのタイトルバー「welcome.txt」のウィンドウ（後ろに 2 枚重ねる）。中に見出し「A word for a feeling you’ve never named」、説明、Start a game と、それを指すマウスカーソルの飾り |
| 設問の提示 | 画面中央に設問のウィンドウを浮かべる |
| チャット | ヘッダー（ワードマークと Give up）、設問のウィンドウ、ログ、入力欄と送信、その下の行にヒントボタンと残りの文字数 |
| 結果 | ログの末尾に、単語を辞書の一項目として組んだウィンドウを積む。タイトルバーに見出し（You found it／The word was）、本文に単語・読み・品詞・直訳・定義・補足・例文の順。ウィンドウの右上の角にホログラムのステッカー（クリアは ✓、ギブアップは旗）を貼り、その下に Play again |

- 起動画面はサイトを開いたときにタブごとに 1 回だけ見せる。打ち終えて一拍おくか Skip を押すとスタート画面へ移り、見たことを `sessionStorage` に記録する。Play again で `/` に戻ったときや、同じタブで開き直したときはスタート画面から始める
- 結果に載せる項目のうち、直訳・補足・例文は単語が持つときだけ出す。読み（カタカナ）は日本語の画面でだけ、単語の下に補足の文字の大きさと色で添える

### コンポーネント基盤

UI は shadcn/ui を土台にし、primitive base に React Aria Components を選ぶ。shadcn のデザインと DX、React Aria のアクセシビリティ実装（キーボード操作・フォーカス管理・スクリーンリーダー対応）を、実装を混在させずに両立させる構成である。

shadcn の見た目のスタイルは Luma（`components.json` の `style` は `aria-luma`）を土台にし、トークンとユーティリティで上の見た目に寄せる。角は `--radius` を 0 にして四角くし、ウィンドウは `window` とタイトルバーの部品（`components/ui/window.tsx`）、主ボタンは `keycap`、副ボタンは `pressable`、フォーカスリングは `focus-ring` で描く。入力欄は白い面に `--input` の 1.5px の枠線で輪郭を示す。入力欄の輪郭は WCAG 1.4.11 の 3:1 を満たす必要があるためである。

### アニメーション

動きは Motion で実装する。ゲーム画面で共有する定義は `components/game/motion.ts` に置く。

| 対象 | 動き |
| --- | --- |
| 起動画面の打ち込み | 0.5 秒おいてから 1 文字ずつ、70〜140ms の揺らぎを持たせて打つ。「!」と改行のあとは 0.42 秒止まる。打ち終えて 0.9 秒おいてスタート画面へ移る。カーソルは 1 秒周期で点滅する |
| スタート画面のウィンドウ | 起動画面から移ったとき、0.92 倍からスプリングで開く。同じタブで開き直したときは動かさない |
| チャットのログに積まれる要素 | 不透明度 0 → 1 と、下 8px からの上方向スライド（0.2 秒） |
| ヒントと結果のウィンドウ | 0.96 倍からの拡大とフェード（0.25 秒） |
| ホログラムのステッカー | 結果のウィンドウが現れてから 0.25 秒おいて、1.8 倍・-40° から押し付けるように縮み、-12° で弾んで止まる（スプリング） |
| 設問の提示 → チャット | 設問のウィンドウが位置と大きさを保ったまま、ヘッダー直下へ変形して収まる（0.4 秒、Motion の `layoutId`）。文字の大きさは切り替えた時点で移し、位置だけを動かす。ヘッダーと入力欄は少し遅れてフェードインする |
| 応答待ち | 読み込みバーの 12 個のブロックが、左から順に灯っては消える（1 周 1.8 秒）。長引いたときの詫びの文言は、ログに積まれる要素と同じ動きで現れる |
| 押せるもの | 押すと影の分（主ボタンは 4px、副ボタンは 2px）だけ沈み、影が消える（0.1 秒） |
| ログのスクロール | 上端の 1.5rem をぼかし、スクロールした要素が設問のウィンドウの下へ消えていくように見せる |

- ルートの `MotionConfig reducedMotion="user"` の配下で動かし、Motion の動きは個別のコンポーネントで reduced motion を判定しない。OS の「視差効果を減らす」が有効なとき、移動・拡大縮小・回転・変形は止まり、不透明度の変化だけが残る
- Motion を使わない起動画面の打ち込みとカーソルの点滅は、自身で reduced motion を判定する。有効なときは文を最初から全部出してカーソルを点滅させず、0.9 秒おいてスタート画面へ移る
- フォーカスの移動とライブリージョンの更新は、要素が DOM に入った時点で行い、動きの完了を待たない

## レスポンシブ設計

### 段階

画面幅を 3 段階に分ける。段階が上がるごとにルートフォントサイズを上げ、rem で組まれたタイポグラフィ・余白・カラム幅を一括でスケールさせる。1 段階ごとに個別のレイアウトを起こすのではなく、同じ構造を拡大して画面の広さに見合う密度にする。

| 段階 | 画面幅 | ルートフォントサイズ | 想定デバイス |
| --- | --- | --- | --- |
| base | 〜767px | 100%（16px） | スマートフォン |
| md | 768px〜1023px | 106.25%（17px） | タブレット・小型ノート |
| lg | 1024px〜 | 112.5%（18px） | デスクトップ |

ルートフォントサイズは `%` で指定し、px で固定しない。ユーザーがブラウザに設定した既定フォントサイズを基準にした相対スケールとして働かせる。

Tailwind のブレークポイント（`md` = 48rem、`lg` = 64rem）はメディアクエリの中で評価され、ブラウザ初期値の 16px を基準に解決される。ルートフォントサイズを段階ごとに変えても、ブレークポイントの位置は 768px / 1024px のまま動かない。

### レイアウト

全画面を単一の中央カラムで構成する。段階が上がってもカラムの数は増やさず、幅と文字サイズだけが連動して大きくなる。

- カラム幅は `42rem`。実効値は base で 672px、md で 714px、lg で 756px
- カラム幅に満たない画面では、左右に `1.25rem` の内側余白を取ってカラムが画面幅いっぱいに広がる
- カラムの外側は背景色のみ。装飾も情報も置かない

プレイ画面は縦 4 段の骨格を全段階で共有する。ヘッダーと入力欄も中央カラムの中に収め、画面全幅には広げない。

| 領域 | 内容 | 振る舞い |
| --- | --- | --- |
| ヘッダー | ワードマーク、Give up | 上部に固定 |
| 設問 | 設問のウィンドウ | ヘッダーの直下に固定 |
| ログ | プレイヤーの発言と回答、正誤、ヒントと結果のウィンドウ、Play again | 縦スクロール。要素が増えたら末尾へ追従 |
| 入力欄 | テキスト入力と送信ボタン、その下の行にヒントボタンと残りの文字数 | 下部に固定 |

- 画面の高さは `100dvh` を基準にし、モバイルのアドレスバー開閉とソフトウェアキーボードの表示に追従させる
- 上下の固定領域には `env(safe-area-inset-*)` を加算し、ノッチとホームインジケータに重ねない

起動画面とスタート画面は上端にワードマークを置く。起動画面はパソコンと Skip を、スタート画面は welcome.txt のウィンドウ（幅は最大 `30rem`）を、中央カラムの中で垂直中央に置く。パソコンは段階によらず幅 `20rem` に保つ。

### 記述ルール

- モバイルファーストで書く。プレフィックスなしの指定を base 段階とし、上の段階との差分だけを `md:` / `lg:` で足す
- 使うブレークポイントは `md` と `lg` の 2 つに限る。`sm:` / `xl:` / `2xl:` と任意幅の `min-[…]` は使わない
- 寸法は rem 由来の Tailwind ユーティリティで指定する。`clamp()` による流体タイポグラフィは使わない。見え方を 3 パターンに閉じ、すべて実機で確認できる状態に保つ

### タップターゲット

操作対象の寸法は WCAG 2.5.8（Target Size (Minimum)）の 24px を最低線とし、入力欄・送信ボタン・ヒントボタン・ギブアップボタンなど、ゲーム進行に必要な操作は 44px 四方を目安に確保する。base 段階では指での操作を前提にこの基準を優先し、密度よりも押しやすさを取る。

### 対象範囲と確認

- 対象は幅 375px 以上。それ未満では横スクロールを許容する
- 確認は 375px / 800px / 1280px の 3 つのビューポートで行い、3 段階それぞれを 1 回ずつ踏む

## アクセシビリティ

### アクセシビリティ方針

方針: 複雑なウィジェットは車輪の再発明をせず shadcn/ui（primitive base: React Aria Components）に任せ、アプリ固有のライブリージョン設計とフォーカス管理に注力する。

- **UI 部品**: shadcn/ui のコンポーネント（ボタン・テキスト入力・ラジオグループ・ダイアログ・プログレスバー等）。ロール、ARIA 属性、キーボード操作、ダイアログのフォーカストラップは内部の React Aria Components が担保する。見た目は自作デザイントークンで与え、フォーカスリングは `focus-ring`（`:focus-visible` と `data-focus-visible` の両方に当たる 2px の濃い輪郭）で常に可視にする
- **多言語対応**: React Aria の `I18nProvider` をルートに置き、支援技術向けの組み込みラベルと日付・数値の書式を ja / en に追従させる
- **ライブリージョン**: AI のはい/いいえ応答と解答の正誤フィードバックを `aria-live` でスクリーンリーダーに通知（チャット型ゲームを非視覚でもプレイ可能にする）
- **フォーカス管理**: 入力送信後は AI 応答へ、ゲーム終了時はチャット末尾の結果のウィンドウ（正解の単語と定義）へフォーカスを移動
- **セマンティック構造**: 見出し階層、`<form>`、ランドマーク、skip link
- **モーション配慮**: アニメーションは Motion で実装し、`MotionConfig reducedMotion="user"` で `prefers-reduced-motion` に一括追従
- **キーボード完結操作**: 全ゲームフローをマウスなしでプレイ可能にする
- **検証の 3 層化**:

  1. eslint-plugin-jsx-a11y（静的解析）
  2. @axe-core/playwright（E2E で自動検証）
  3. VoiceOver での手動テスト

### 画面上の反映

- AI の回答・解答の正誤フィードバック・送信とヒントの失敗はライブリージョンで読み上げる。やり取りログ全体を `aria-live` にはせず、新規に確定した要素だけを通知対象にする。ヒント・プレイヤーの発言・結果のウィンドウはフォーカスの移動で読ませるため、ライブリージョンには載せない
- フォーカスは次のとおり移す。設問の提示からチャットへの遷移では動かさない

  | 契機 | 移動先 |
  | --- | --- |
  | 送信への回答・誤答 | 確定した回答・正誤フィードバック |
  | ヒントの開示 | 開示したヒントのウィンドウ |
  | 送信の失敗 | 入力欄（送った文字列を戻し、そのまま再送できる） |
  | ヒントの失敗 | ヒントボタン |
  | 正解・ギブアップ | 結果のウィンドウの見出し |
  | 起動画面の Skip を押したとき、または Skip にフォーカスがあるまま打ち終えたとき | スタート画面の見出し |

- 見出しは、プレイ画面ではヘッダーのワードマークを `h1` にする。ヘッダーのない開始待ちと設問の提示では、視覚的に隠した `h1` を置く。起動画面では打ち込む文「Hej hej! Jag heter Kotoba」を視覚的に隠した `h1` にして `lang="sv"` を付け、パソコンの画面の文字は読み上げない。スタート画面では見出し「A word for a feeling you’ve never named」を `h1` にする。`<header>` は `<main>` の外に置いてバナーのランドマークにする
- skip link を Tab の最初に置き、入力欄へ飛ばす。Tab の順序は skip link → Give up → 入力欄 → 送信ボタン → ヒントボタン
- 設問の提示は Enter / Space とクリックで進める。Tab やスクリーンリーダーの操作キーで設問を読む前に進まないよう、それ以外のキーでは進めない
- 回答の 5 値、判定と案内、ラベルの区別を色だけに頼らず、形（ピル／塗りのない文字）・アイコン・文字で成立させる
- 正解の単語と例文の原文には `lang="sv"` を付け、スクリーンリーダーにスウェーデン語として読ませる
- ホログラムのステッカー、起動画面のパソコン、ウィンドウのタイトルバーの箱と重ねたウィンドウ、スタート画面のマウスカーソルとタイトル「welcome.txt」は `aria-hidden` にし、読み上げない
- 起動画面の Skip の「>」は `aria-hidden` にし、ボタンの名前は「Skip」にする
