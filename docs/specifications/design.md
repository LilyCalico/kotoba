## 画面設計

### figma 草案

https://www.figma.com/design/mWFhHDTqPHFBKhIMrkKj9B/Kotoba?node-id=112-16215&t=neuwj2UIPBPtq3WG-4

### トーン&マナー

- 方向性: **Y2K パステル**。淡いペリウィンクルの地に、白い四角いカードと 1px の焦げ茶の罫を置き、パステルの丸いピルで回答を返す。Astryx の Y2K テーマを下敷きにしている
- 見せ場は 1 つに絞る。正解とギブアップで、結果のカードにホログラムのステッカーが貼られる瞬間だけを演出し、ほかの動きは状態の変化を伝える短い出現にとどめる
- モバイル・デスクトップの両対応を同等品質で作り込む。画面幅ごとのレイアウトは「レスポンシブ設計」節で定める
- テーマはライトのみ。配色はすべてセマンティックトークン経由で参照し、ダークを足すときは値の差し替えだけで済む形にしておく

### デザイントークン

値は `apps/web/app/globals.css` の `:root` に置く。

| 種類 | トークン | 値 | 使い道 |
| --- | --- | --- | --- |
| 地 | `--background` | `#e1e3fd` | 画面の地 |
| 文字 | `--foreground` | `#2d241b` | 本文 |
| 補足の文字 | `--muted-foreground` | `#675d52` | 補足、残りの文字数、ヒントの番号 |
| 面 | `--card` | `#ffffff` | 設問・ヒント・結果のカード、入力欄、ダイアログ、トースト |
| 罫 | `--border` / `--input` | `#382e24` | カードとコントロールの 1px の輪郭 |
| 主ボタン | `--primary` | `#c5e17a`（ライム） | 送信・Start a game・Play again |
| 副ボタン | `--secondary` | `#ffffff` | ヒント・Cancel |
| 取り消せない操作 | `--destructive` | `#ffc3c3` | ギブアップの確定 |
| 発言 | `--bubble` | `#2d241b` | プレイヤーの発言の吹き出し |
| ラベル | `--label` | `#dcd0ff`（ラベンダー） | Question・品詞 |
| 回答 | `--answer-yes` / `--answer-no` / `--answer-unclear` / `--answer-meta` | `#c5e17a` / `#ffbfd9` / `#addbff` / `#ffe08a` | 回答のピル |
| 例文の下地 | `--muted` | `#f1e6db` | 結果の例文 |
| フォーカス | `--ring` | `#2d241b` | フォーカスリング |

| 種類 | 値 |
| --- | --- |
| 書体 | Poppins（UI）／ Crimson Text（設問・ヒント・正解の単語と定義・ダイアログの見出し） |
| 角 | 0（`--radius`）。ピル（`rounded-full`）と吹き出しだけを丸める |
| 影 | 押せるものだけに、3px（大きなボタンは 4px）ずらしたベタの影（`--shadow-press`）。押すと影の分だけ沈んで影が消える |
| ホログラム | 回答とラベルの色を巡る円錐グラデーション（`holo`）。ステッカーにだけ使う |

文字の組み合わせはすべて WCAG 1.4.3 の 4.5:1、罫とフォーカスリングは 1.4.11 の 3:1 を満たす。比は `docs/guides/frontend-ui.md` の手順 4 に一覧がある。

### 役割ごとの見た目

画面の要素は役割ごとに見た目を 1 つに決め、同じ見た目を別の役割に使わない。

| 役割 | 要素 | 見た目 |
| --- | --- | --- |
| 回答 | 5 値の回答 | アイコン付きの太字の丸いピル。Yes はライムに ✓、No はピンクに ✕、Hard to say は空色に −、That's not related は白に破線の枠と切れた鎖、Try a yes-or-no question は黄に吹き出しの ? |
| 判定と案内 | 正誤のフィードバック、送信とヒントの失敗、期限切れ | 塗りも枠もない、アイコン付きの文字 |
| 応答待ち | 応答待ちの点 | 回答のピルが入る位置の、破線の枠のピル |
| ラベル | 設問の Question、結果の品詞 | ラベンダーの小さなピル。回答より小さく、アイコンを付けない |
| 発言 | プレイヤーの入力、ヒントの要求 | 焦げ茶の吹き出しに白い文字。右に寄せ、右下の角だけを尖らせる |
| 読ませるもの | 設問・ヒント・結果 | 白い四角いカードに 1px の罫。影は付けない。本文は Crimson Text |
| 押せるもの | 送信・Start a game・Play again・ヒント・Cancel・ギブアップの確定 | 1px の罫とずらした影。主はライム、副は白、取り消せない操作は淡い赤に旗のアイコン |
| 目立たせない操作 | ヘッダーの Give up | 旗のアイコンと下線の付いた文字。枠も影も持たない |

- ライムは主ボタンと Yes の回答に共通する。形（四角と影／丸いピル）とアイコンの有無で見分ける
- ヒントの残りの回数は、ヒントボタンの中の 3 つの点で示す。塗った点が残りの数になる。読み上げでは「Show a hint, 2 left」のように数を伝える
- ヒントの番号は、カードの左上に電球のアイコンと「Hint 1 of 3」の小さな文字で添える

### 画面

| 画面 | 構成 |
| --- | --- |
| スタート | ワードマーク、空欄のカードを 2 枚重ねて「?」のステッカーを貼った飾り、見出し「A word for a feeling you’ve never named」、説明、Start a game |
| 設問の提示 | 画面中央に設問のカードを浮かべる |
| チャット | ヘッダー（ワードマークと Give up）、設問のカード、ログ、入力欄と送信、その下の行にヒントボタンと残りの文字数 |
| 結果 | ログの末尾に、単語を辞書の一項目として組んだカードを積む。見出し（You found it／The word was）・単語・品詞・直訳・定義・補足・例文の順。右上にホログラムのステッカー（クリアは ✓、ギブアップは旗）を貼り、その下に Play again |

結果に載せる項目のうち、直訳・補足・例文は単語が持つときだけ出す。

### コンポーネント基盤

UI は shadcn/ui を土台にし、primitive base に React Aria Components を選ぶ。shadcn のデザインと DX、React Aria のアクセシビリティ実装（キーボード操作・フォーカス管理・スクリーンリーダー対応）を、実装を混在させずに両立させる構成である。

shadcn の見た目のスタイルは Luma（`components.json` の `style` は `aria-luma`）を土台にし、トークンとユーティリティで上の見た目に寄せる。角は `--radius` を 0 にして四角くし、枠と影を持つボタンは `pressable`、フォーカスリングは `focus-ring` で描く。入力欄は白い面に `--input` の 1px の枠線で輪郭を示す。入力欄の輪郭は WCAG 1.4.11 の 3:1 を満たす必要があるためである。

### アニメーション

動きは Motion で実装する。共有する定義は `components/game/motion.ts` に置く。

| 対象 | 動き |
| --- | --- |
| チャットのログに積まれる要素 | 不透明度 0 → 1 と、下 8px からの上方向スライド（0.2 秒） |
| ヒントカード・結果カード | 0.96 倍からの拡大とフェード（0.25 秒） |
| ホログラムのステッカー | 結果カードが現れてから 0.25 秒おいて、1.8 倍・-40° から押し付けるように縮み、-10° で弾んで止まる（スプリング）。画面で唯一の演出 |
| 設問の提示 → チャット | 設問カードが位置と大きさを保ったまま、ヘッダー直下へ変形して収まる（0.4 秒、Motion の `layoutId`）。文字の大きさは切り替えた時点で移し、位置だけを動かす。ヘッダーと入力欄は少し遅れてフェードインする |
| 応答待ちインジケーター | 点の不透明度のループ |
| 押せるもの | 押すと影の分（3px）だけ沈み、影が消える（0.1 秒） |
| ログのスクロール | 上端の 1.5rem をぼかし、スクロールした要素が設問カードの下へ消えていくように見せる |

- ルートの `MotionConfig reducedMotion="user"` の配下で動かし、個別のコンポーネントでは reduced motion を判定しない。OS の「視差効果を減らす」が有効なとき、移動・拡大縮小・回転・変形は止まり、不透明度の変化だけが残る
- フォーカスの移動とライブリージョンの更新は、要素が DOM に入った時点で行い、動きの完了を待たない

## レスポンシブ設計

### 段階

画面幅を 3 段階に分ける。段階が上がるごとにルートフォントサイズを上げ、rem で組まれたタイポグラフィ・余白・カラム幅を一括でスケールさせる。1 段階ごとに個別のレイアウトを起こすのではなく、同じ構造を拡大して画面の広さに見合う密度にする。

| 段階 | 画面幅 | ルートフォントサイズ | 想定デバイス |
| --- | --- | --- | --- |
| base | 〜767px | 100%（16px） | スマートフォン |
| md | 768px〜1023px | 106.25%（17px） | タブレット・小型ノート |
| lg | 1024px〜 | 112.5%（18px） | デスクトップ |

ルートフォントサイズは `%` で指定し、px で固定しない。ユーザーがブラウザに設定した既定フォントサイズを基準にした相対スケールとして働かせる。

Tailwind のブレークポイント（`md` = 48rem、`lg` = 64rem）はメディアクエリの中で評価され、ブラウザ初期値の 16px を基準に解決される。ルートフォントサイズを段階ごとに変えても、ブレークポイントの位置は 768px / 1024px のまま動かない。

### レイアウト

全画面を単一の中央カラムで構成する。段階が上がってもカラムの数は増やさず、幅と文字サイズだけが連動して大きくなる。

- カラム幅は `42rem`。実効値は base で 672px、md で 714px、lg で 756px
- カラム幅に満たない画面では、左右に `1.25rem` の内側余白を取ってカラムが画面幅いっぱいに広がる
- カラムの外側は背景色のみ。装飾も情報も置かない

プレイ画面は縦 4 段の骨格を全段階で共有する。ヘッダーと入力欄も中央カラムの中に収め、画面全幅には広げない。

| 領域 | 内容 | 振る舞い |
| --- | --- | --- |
| ヘッダー | ワードマーク、Give up | 上部に固定 |
| 設問 | 設問カード | ヘッダーの直下に固定 |
| ログ | プレイヤーの発言と回答、正誤、ヒントカード、結果カード、Play again | 縦スクロール。要素が増えたら末尾へ追従 |
| 入力欄 | テキスト入力と送信ボタン、その下の行にヒントボタンと残りの文字数 | 下部に固定 |

- 画面の高さは `100dvh` を基準にし、モバイルのアドレスバー開閉とソフトウェアキーボードの表示に追従させる
- 上下の固定領域には `env(safe-area-inset-*)` を加算し、ノッチとホームインジケータに重ねない

スタート画面は上端にワードマークを置き、空欄のカードの飾り・見出し・説明文を中央カラムの中で垂直中央に積み、Start a game を下端に置く。

### 記述ルール

- モバイルファーストで書く。プレフィックスなしの指定を base 段階とし、上の段階との差分だけを `md:` / `lg:` で足す
- 使うブレークポイントは `md` と `lg` の 2 つに限る。`sm:` / `xl:` / `2xl:` と任意幅の `min-[…]` は使わない
- 寸法は rem 由来の Tailwind ユーティリティで指定する。`clamp()` による流体タイポグラフィは使わない。見え方を 3 パターンに閉じ、すべて実機で確認できる状態に保つ

### タップターゲット

操作対象の寸法は WCAG 2.5.8（Target Size (Minimum)）の 24px を最低線とし、入力欄・送信ボタン・ヒントボタン・ギブアップボタンなど、ゲーム進行に必要な操作は 44px 四方を目安に確保する。base 段階では指での操作を前提にこの基準を優先し、密度よりも押しやすさを取る。

### 対象範囲と確認

- 対象は幅 375px 以上。それ未満では横スクロールを許容する
- 確認は 375px / 800px / 1280px の 3 つのビューポートで行い、3 段階それぞれを 1 回ずつ踏む

## アクセシビリティ

### アクセシビリティ方針

方針: 複雑なウィジェットは車輪の再発明をせず shadcn/ui（primitive base: React Aria Components）に任せ、アプリ固有のライブリージョン設計とフォーカス管理に注力する。

- **UI 部品**: shadcn/ui のコンポーネント（ボタン・テキスト入力・ラジオグループ・ダイアログ・プログレスバー等）。ロール、ARIA 属性、キーボード操作、ダイアログのフォーカストラップは内部の React Aria Components が担保する。見た目は自作デザイントークンで与え、フォーカスリングは `focus-ring`（`:focus-visible` と `data-focus-visible` の両方に当たる 2px の濃い輪郭）で常に可視にする
- **多言語対応**: React Aria の `I18nProvider` をルートに置き、支援技術向けの組み込みラベルと日付・数値の書式を ja / en に追従させる
- **ライブリージョン**: AI のはい/いいえ応答と解答の正誤フィードバックを `aria-live` でスクリーンリーダーに通知（チャット型ゲームを非視覚でもプレイ可能にする）
- **フォーカス管理**: 入力送信後は AI 応答へ、ゲーム終了時はチャット末尾の結果カード（正解の単語と定義）へフォーカスを移動
- **セマンティック構造**: 見出し階層、`<form>`、ランドマーク、skip link
- **モーション配慮**: アニメーションは Motion で実装し、`MotionConfig reducedMotion="user"` で `prefers-reduced-motion` に一括追従
- **キーボード完結操作**: 全ゲームフローをマウスなしでプレイ可能にする
- **検証の 3 層化**:

  1. eslint-plugin-jsx-a11y（静的解析）
  2. @axe-core/playwright（E2E で自動検証）
  3. VoiceOver での手動テスト

### 画面上の反映

- AI の回答・解答の正誤フィードバック・送信とヒントの失敗はライブリージョンで読み上げる。やり取りログ全体を `aria-live` にはせず、新規に確定した要素だけを通知対象にする。ヒント・プレイヤーの発言・結果カードはフォーカスの移動で読ませるため、ライブリージョンには載せない
- フォーカスは次のとおり移す。設問の提示からチャットへの遷移では動かさない

  | 契機 | 移動先 |
  | --- | --- |
  | 送信への回答・誤答 | 確定した回答・正誤フィードバック |
  | ヒントの開示 | 開示したヒントカード |
  | 送信の失敗 | 入力欄（送った文字列を戻し、そのまま再送できる） |
  | ヒントの失敗 | ヒントボタン |
  | 正解・ギブアップ | 結果カードの見出し |

- 見出しは、プレイ画面ではヘッダーのワードマークを `h1` にする。ヘッダーのない開始待ちと設問の提示では、視覚的に隠した `h1` を置く。スタート画面では見出し「A word for a feeling you’ve never named」を `h1` にする。`<header>` は `<main>` の外に置いてバナーのランドマークにする
- skip link を Tab の最初に置き、入力欄へ飛ばす。Tab の順序は skip link → Give up → 入力欄 → 送信ボタン → ヒントボタン
- 設問の提示は Enter / Space とクリックで進める。Tab やスクリーンリーダーの操作キーで設問を読む前に進まないよう、それ以外のキーでは進めない
- 回答の 5 値、判定と案内、ラベルの区別を色だけに頼らず、形（ピル／塗りのない文字）・アイコン・文字で成立させる
- 正解の単語と例文の原文には `lang="sv"` を付け、スクリーンリーダーにスウェーデン語として読ませる
- ホログラムのステッカーとスタート画面の飾りは `aria-hidden` にし、読み上げない
