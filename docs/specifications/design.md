## 画面設計

### トーン&マナー / デザイントークン方針

- 方向性: **余白を活かしたミニマル**。無彩色ベースの背景とテキストに、ロゴの緑をアクセント 1 色として最小限に添える
- モバイル・デスクトップの両対応を同等品質で作り込む。画面幅ごとのレイアウトは「レスポンシブ設計」節で定める
- テーマはライトのみ。配色はすべてセマンティックトークン経由で参照し、テーマ追加時に値の差し替えだけで済む形にしておく

### コンポーネント基盤

UI は shadcn/ui を土台にし、primitive base に React Aria Components を選ぶ。shadcn のデザインと DX、React Aria のアクセシビリティ実装（キーボード操作・フォーカス管理・スクリーンリーダー対応）を、実装を混在させずに両立させる構成である。

shadcn の見た目のスタイルは Luma（`components.json` の `style` は `aria-luma`）。大きな角丸と広めの余白をとり、ボタンは両端が丸く、ダイアログは影を落として浮かぶ。丸ゴシックの書体と淡い緑の配色に合う柔らかさを優先する。ただし入力欄だけは Luma の塗りを使わず、`--input` の枠線で輪郭を示す。入力欄の輪郭は WCAG 1.4.11 の 3:1 を満たす必要があるためである。

### アニメーション

動きは Motion で実装し、状態の変化を伝える短い出現に絞る。共有する出現の定義は `components/game/motion.ts` に置く。

| 対象 | 動き |
| --- | --- |
| チャットのログに積まれる要素 | 不透明度 0 → 1 と、下 8px からの上方向スライド（0.2 秒） |
| ヒントカード・結果カード | 0.96 倍からの拡大とフェード（0.25 秒） |
| 設問の提示 → チャット | 設問カードが位置と大きさを保ったまま、ヘッダー直下へ変形して収まる（0.4 秒、Motion の `layoutId`）。文字の大きさは切り替えた時点で移し、位置だけを動かす。ヘッダーと入力欄は少し遅れてフェードインし、背景の葉はフェードアウトする |
| 応答待ちインジケーター | 点の不透明度のループ |
| 背景の葉 | 左右に揺れながら舞い落ちるループ |

- ルートの `MotionConfig reducedMotion="user"` の配下で動かし、個別のコンポーネントでは reduced motion を判定しない。OS の「視差効果を減らす」が有効なとき、移動・拡大縮小・変形は止まり、不透明度の変化だけが残る。背景の葉だけは、止めたときに草案の座標へ置き直す必要があるため自身で判定する
- フォーカスの移動とライブリージョンの更新は、要素が DOM に入った時点で行い、動きの完了を待たない

## レスポンシブ設計

### 段階

画面幅を 3 段階に分ける。段階が上がるごとにルートフォントサイズを上げ、rem で組まれたタイポグラフィ・余白・カラム幅を一括でスケールさせる。1 段階ごとに個別のレイアウトを起こすのではなく、同じ構造を拡大して画面の広さに見合う密度にする。

| 段階 | 画面幅 | ルートフォントサイズ | 想定デバイス |
| --- | --- | --- | --- |
| base | 〜767px | 100%（16px） | スマートフォン |
| md | 768px〜1023px | 106.25%（17px） | タブレット・小型ノート |
| lg | 1024px〜 | 112.5%（18px） | デスクトップ |

ルートフォントサイズは `%` で指定し、px で固定しない。ユーザーがブラウザに設定した既定フォントサイズを基準にした相対スケールとして働かせる。

Tailwind のブレークポイント（`md` = 48rem、`lg` = 64rem）はメディアクエリの中で評価され、ブラウザ初期値の 16px を基準に解決される。ルートフォントサイズを段階ごとに変えても、ブレークポイントの位置は 768px / 1024px のまま動かない。

### レイアウト

全画面を単一の中央カラムで構成する。段階が上がってもカラムの数は増やさず、幅と文字サイズだけが連動して大きくなる。

- カラム幅は `42rem`。実効値は base で 672px、md で 714px、lg で 756px
- カラム幅に満たない画面では、左右に `1rem` の内側余白を取ってカラムが画面幅いっぱいに広がる
- カラムの外側は背景色のみ。装飾も情報も置かない

プレイ画面は縦 3 分割の骨格を全段階で共有する。ヘッダーと入力欄も中央カラムの中に収め、画面全幅には広げない。

| 領域 | 内容 | 振る舞い |
| --- | --- | --- |
| ヘッダー | ロゴ、ギブアップボタン | 上部に固定 |
| ログ | 設問カード、プレイヤーの質問と AI の回答、ヒントカード、結果カード | 縦スクロール。要素が増えたら末尾へ追従 |
| 入力欄 | テキスト入力、送信ボタン、ヒントボタン | 下部に固定 |

- 画面の高さは `100dvh` を基準にし、モバイルのアドレスバー開閉とソフトウェアキーボードの表示に追従させる
- 上下の固定領域には `env(safe-area-inset-*)` を加算し、ノッチとホームインジケータに重ねない

スタート画面はロゴ・説明文・START ボタンを縦に積み、中央カラムの中で垂直中央に置く。

### 記述ルール

- モバイルファーストで書く。プレフィックスなしの指定を base 段階とし、上の段階との差分だけを `md:` / `lg:` で足す
- 使うブレークポイントは `md` と `lg` の 2 つに限る。`sm:` / `xl:` / `2xl:` と任意幅の `min-[…]` は使わない
- 寸法は rem 由来の Tailwind ユーティリティで指定する。`clamp()` による流体タイポグラフィは使わない。見え方を 3 パターンに閉じ、すべて実機で確認できる状態に保つ

### タップターゲット

操作対象の寸法は WCAG 2.5.8（Target Size (Minimum)）の 24px を最低線とし、入力欄・送信ボタン・ヒントボタン・ギブアップボタンなど、ゲーム進行に必要な操作は 44px 四方を目安に確保する。base 段階では指での操作を前提にこの基準を優先し、密度よりも押しやすさを取る。

### 対象範囲と確認

- 対象は幅 375px 以上。それ未満では横スクロールを許容する
- 確認は 375px / 800px / 1280px の 3 つのビューポートで行い、3 段階それぞれを 1 回ずつ踏む

## アクセシビリティ

### アクセシビリティ方針

方針: 複雑なウィジェットは車輪の再発明をせず shadcn/ui（primitive base: React Aria Components）に任せ、アプリ固有のライブリージョン設計とフォーカス管理に注力する。

- **UI 部品**: shadcn/ui のコンポーネント（ボタン・テキスト入力・ラジオグループ・ダイアログ・プログレスバー等）。ロール、ARIA 属性、キーボード操作、ダイアログのフォーカストラップは内部の React Aria Components が担保する。見た目は自作デザイントークンで与え、フォーカスリングは `data-[focus-visible]` に当てて常に可視にする
- **多言語対応**: React Aria の `I18nProvider` をルートに置き、支援技術向けの組み込みラベルと日付・数値の書式を ja / en に追従させる
- **ライブリージョン**: AI のはい/いいえ応答と解答の正誤フィードバックを `aria-live` でスクリーンリーダーに通知（チャット型ゲームを非視覚でもプレイ可能にする）
- **フォーカス管理**: 入力送信後は AI 応答へ、ゲーム終了時はチャット末尾の結果カード（正解の単語と定義）へフォーカスを移動
- **セマンティック構造**: 見出し階層、`<form>`、ランドマーク、skip link
- **モーション配慮**: アニメーションは Motion で実装し、`MotionConfig reducedMotion="user"` で `prefers-reduced-motion` に一括追従
- **キーボード完結操作**: 全ゲームフローをマウスなしでプレイ可能にする
- **検証の 3 層化**:

  1. eslint-plugin-jsx-a11y（静的解析）
  2. @axe-core/playwright（E2E で自動検証）
  3. VoiceOver での手動テスト

### 画面上の反映

- AI の回答・解答の正誤フィードバック・送信とヒントの失敗はライブリージョンで読み上げる。やり取りログ全体を `aria-live` にはせず、新規に確定した要素だけを通知対象にする。ヒント・プレイヤーの発言・結果カードはフォーカスの移動で読ませるため、ライブリージョンには載せない
- フォーカスは次のとおり移す。設問の提示からチャットへの遷移では動かさない

  | 契機 | 移動先 |
  | --- | --- |
  | 送信への回答・誤答 | 確定した回答・正誤フィードバック |
  | ヒントの開示 | 開示したヒントカード |
  | 送信の失敗 | 入力欄（送った文字列を戻し、そのまま再送できる） |
  | ヒントの失敗 | ヒントボタン |
  | 正解・ギブアップ | 結果カードの見出し |

- 見出しはヘッダーのロゴを `h1` にする。ヘッダーのない開始待ちと設問の提示では、視覚的に隠した `h1` を置く。`<header>` は `<main>` の外に置いてバナーのランドマークにする
- skip link を Tab の最初に置き、入力欄へ飛ばす。Tab の順序は skip link → Give up → ヒントボタン → 入力欄 → 送信ボタン
- 設問の提示は Enter / Space とクリックで進める。Tab やスクリーンリーダーの操作キーで設問を読む前に進まないよう、それ以外のキーでは進めない
- ヒントとメタ応答の区別を、色ではなくアイコン・枠線・補助テキストで成立させる
